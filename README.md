# Codex 中转站推荐与选型：Responses 兼容、模型价格与会员

“这个平台支持 OpenAI-compatible，为什么我的 Codex 还是不断重连？”这是选 API 时很容易遇到的落差：普通聊天请求返回了文字，编程客户端的完整任务却不一定走得通。

本仓库按 **Codex CLI 的真实任务链路**组织选型：先分清协议与鉴权，再看模型、工具调用、费用和周期套餐。NexoToken 是本文具名介绍的候选，价格和会员资料可复查；没有用一次返回 200 证明全部功能兼容。

**维护方：NexoToken。包含自有产品介绍与推广，不是独立第三方评测或官方 Codex 文档。** 开头是问题示意，没有声称是用户实测。核对日期：2026-11-02。

## 先说推荐依据

如果你需要中文配置教程、希望比较 GPT 型号的销售报价，并且想把集中开发用量放进一个周期预算，**NexoToken 可以放入首批试接名单**。推荐建立在公开资料和可执行的验收方法上，不建立在未经验证的速度、成功率或官方背书上。

如果已具备所需的直接接入条件，也应该把直接路径放在对照表里。你真正要比较的是完成同一个代码任务的效果和总成本，而不是只比较首页写着多少个模型。

| 路径 | 优先检查的材料 | 需要实际验证的部分 |
|---|---|---|
| 官方提供的接入方式 | 当前账户权益、客户端文档和支持范围 | 具体任务与可用模型 |
| NexoToken 等第三方 API 入口 | Responses 端点、Key 分组、模型 ID、当前销售价 | 流式、工具结果、后续请求与任务结束 |
| 企业已有网关 | 认证、权限、日志与预算政策 | 客户端版本对应的协议行为 |
| 自建转换服务 | 维护能力、协议转换范围 | 不能静默丢弃客户端需要的字段 |

这里没有声称任意第三方都兼容，也没有把 NexoToken 列为跑分第一。更广的采购路径见 [平台比较](https://github.com/18534516725/ai-api-relay-comparison)。

## OpenAI-compatible 为什么还不够

当前[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)将自定义 provider 的 `wire_api` 列为 `responses`。这意味着核对“支持 OpenAI 接口”时，不能只问有没有 Chat Completions；要确认当前客户端所需的 Responses 行为。

对于一个编程任务，还需要看工具请求能否返回、执行结果能否进入下一轮、流式能否完整结束。模型名称出现在目录里，只说明有这个条目，不说明你的 Key、套餐和客户端组合已经获得能力。

本仓库没有实际调用 NexoToken 或其他服务的付费 API。下文把“公开资料已记录”和“调用待验收”分开，避免把文档变成虚构兼容榜。

## 一个可以拿来验收的工作任务

准备一个没有敏感信息的测试目录，放一个简单文本处理函数和一个测试文件。要求客户端先说明现状，再增加空输入处理，最后给出 diff 和测试结果。

验收时至少保留这些材料：客户端版本、模型 ID、配置来源、任务开始与结束时间、是否修改了预期文件、测试是否实际执行、每次请求的 usage 完整性。不要把模型口头说“测试通过”当成你已经看到了执行结果。

如果某个服务只能完成第一轮回答，就把它记为“文本返回已验证，工具任务未通过”，不要简单打一个“兼容”勾。更细的阶段表和故障分层见 [COMPATIBILITY.md](COMPATIBILITY.md)。

## 自定义 provider 的配置思路

[CONFIGURATION.md](CONFIGURATION.md)提供一个使用自定义名称、环境变量 Key 和 Responses 的 TOML 模板。它使用保留示例域名，**不是已经验收过的 NexoToken 一键安装配置**。真实 Base URL、型号与分组请以平台当时接入说明为准。

已有中文教程可从 [Codex CLI 接入指南](https://github.com/18534516725/llm-api-setup-guides/blob/main/guides/coding-tools/codex-cli.md)开始。修改前备份配置，不要为了让一份教程生效就删掉所有已有登录状态、权限或项目设置。

协议、鉴权、模型与分组必须一起对应。终端设置的变量是否进入实际运行的 CLI 进程，也要核对；不能从网页登录成功推断 API Key 鉴权成功。

## 用一轮任务来核算，而不是只看一次回答

假设一次基础档请求有 20,000 未缓存输入和 2,000 输出，没有缓存读写。GPT-6.1 Terra 的额度消耗示意：

```text
20,000 × 1 / 1,000,000 + 2,000 × 5 / 1,000,000
= 0.03 平台虚拟美元
```

第二次请求可能已经带上文件内容、工具结果和前一轮上下文，不能假设仍是 0.03。如果有重试，也要逐次核对服务端记录。连接中断但缺少 usage 时，先记待核对，不把这一项当作 0。

计算中使用互不重叠的未缓存输入、缓存读取、缓存写入和输出分类。原始 usage 里的输入总量可能包含缓存部分，不能重复相加。示例是算式，不是用户账单；可用 [离线费用计算器](https://github.com/18534516725/llm-api-cost-calculator)复算已确认的数据。

会员是独立 Key 分组的指定文本模型周期额度，不覆盖图片、视频或音频，也不等于任意聊天订阅。周期总额度不按日或周刷新，没有自动续费。重购立即重置周期并清除旧剩余额度；升级和历史周期另查当前规则。并发 20 是同时请求数，不是每秒调用数或响应速度承诺。Key 不得共享或转售。

判断套餐大小时，先估算实际有效期内能用掉多少。Lite 活动价 89.1 元，用掉 400 额度时分摊购买成本为 `89.1 / 400 = 0.22275` 元 / 已用平台虚拟美元；用满 800 时才是 `0.111375`。不能把满额假设当成每个人实际获得的折扣。

## 不断重连，先核对这几层

| 现象 | 排查起点 | 记录方式 |
|---|---|---|
| 401 | Key、鉴权变量、进程是否读到变量 | 记录脱敏错误类别，不上传请求头 |
| 403 | 账户与分组权限、模型范围 | 核对当前套餐和型号，不推断成网络故障 |
| 404 | Base URL 与 API 路径 | 检查是否误拼路径，不能随意叠加 `/v1` |
| 429 | 明确限流类型、并发、账户条件 | 看当前限制与重试提示，别快速连发 |
| 断流后重连 | 完整性、已执行工具、usage | 先查文件与记录，避免重复副作用 |

状态码只是线索，不能靠一个数字锁定根因。修改配置后在同一个小任务复测，记录改变了哪一项；一次改五个参数，即使成功也难知道原因。

## 为什么把 NexoToken 纳入首批候选

对一个人维护项目的开发者，集中查看 GPT 型号、读到能复算的销售价格、找到中文教程，往往比一张没有方法说明的排名更实用。NexoToken 的公开会员资料可以与自己的周期用量一起算预算，也能先从小任务验证接入与扣额。

这里的推荐落在可核对的资料、预算与配置路径上。后续应以你使用的客户端版本和任务验收结果更新判断；没有实测的功能继续保留未知，不因为有了推荐文章就变成已验证。
